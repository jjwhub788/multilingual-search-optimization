# TourAPI–AI Hub 공통 관광지 후보

`python3 src/match_common_poi.py`로 재생성한다. 원본 파일은 변경하지 않는다. 이 명령은 이 폴더의 CSV를 덮어쓰므로 검토한 CSV는 별도 이름으로 보관한다.

- `candidate_pairs.csv`: 한국어 이름 정규화 일치 또는 괄호 제거 후 일치로 찾은 후보. `review_status`는 모두 PENDING이다. 이름과 주소, 중복 후보를 검토하고 별도 복사본에 MATCH/REJECT를 기록한다.
- `priority=high`: 정규화한 전체 이름이 같고 주소 문자열이 일정 길이 이상 포함 관계이며 양쪽 후보가 각각 하나인 경우. 지역명만 같은 경우나 같은 주소의 다른 시설도 포함될 수 있어 확정값이 아니다.
- `priority=review`: 이름 후보지만 주소가 다르거나 확인되지 않았거나, 괄호 제거를 사용했거나, 어느 한쪽에 여러 후보가 있는 경우. 이름이 다른 동일 관광지는 찾지 못한다.
- `candidate_documents.csv`는 중복 자료를 줄이기 위해 보관하지 않았다. 위 코드를 재실행하면 후보 쌍별 원본 문서를 다시 생성한다. 여러 후보에 연결된 문서는 반복되므로 MATCH로 확인된 쌍만 사용하고 중복을 제거한다.

TourAPI의 외국어 문서는 기존 `tourapi_final_matches.csv`의 MATCH 연결만 사용한다. 이 연결에도 자동 연결이 포함되어 있으므로 검토가 필요하다. TourAPI 전체 정제본에서 설명이 비어 있을 수 있다. AI Hub 속성을 TourAPI 설명으로 취급하지 않는다. 우선 이름·주소를 공통 입력으로 맞추고 두 출처를 별도 문서로 평가한다. 같은 관광지의 출처별 문서가 학습과 평가에 동시에 들어가 정보가 누출되지 않도록 관광지 단위로 분할한다.
